## Lane 4 – Console scaffold (`pph-console`)

### Goal
A Bun‑powered React frontend that:
- Serves the gallery from `thumbs.json`
- Renders docs from `mdHtml`
- Shows the live overview (cash position, agents, skins, health)
- Displays the matrix for any skin (via `/skins/:slug/limits`)
- Integrates with the score gate and contracts registry

### Technical decisions (based on Bun build docs and our architecture)

| Aspect | Choice |
| :----- | :----- |
| **Workspace** | `pph-console` – a new workspace in the catalog |
| **Framework** | React 18 (with `react-dom`) – we already have the `reactVersion: 18` flag for markdown |
| **Bundler** | Bun's native bundler (no Webpack/Vite) |
| **Build config** | `bun build` with options: `naming`, `root`, `publicPath`, `define`, `features`, `metafile` |
| **Dev server** | `bun --hot` + Bun's built‑in `serve` |
| **Styling** | TailwindCSS (detected automatically by `bun create`, but we'll set it up) |
| **Routing** | File‑based routing (like Next.js but lighter) – `pages/` directory |
| **Data** | All data comes from the existing `pph-api` routes (`/overview`, `/skins/:slug/limits`, `/reports`, `/score`) – we'll proxy them during dev |
| **Testing** | Bun's native test runner with `react-testing-library` (optional) |

### Scaffolding steps

1. **Create the workspace**
   ```bash
   bun run new:workspace pph-console
   ```
   This uses our workspace generator (with guards) to create the new package.

2. **Install dependencies**
   ```bash
   cd packages/pph-console
   bun add react react-dom tailwindcss bun-plugin-tailwind
   bun add -d @types/react @types/react-dom
   ```

3. **Set up the build script** – `build.console.ts`
   - Entrypoints: `./pages/index.tsx`, `./pages/overview.tsx`, `./pages/skin/[slug].tsx`
   - `naming: 'files/[dir]/[name]-[hash].[ext]'`
   - `root: '.'` to preserve `pages/` structure
   - `publicPath: '/static/'` (or relative)
   - `define: { 'process.env.VERSION': JSON.stringify(await getGitVersion()) }`
   - `features: ['DEBUG']` (for development; can be overridden with `--feature` flags)
   - `metafile: { json: './dist/meta.json', markdown: './dist/meta.md' }`
   - `drop: process.env.NODE_ENV === 'production' ? ['console'] : []`

4. **Create the directory structure**
   ```
   packages/pph-console/
   ├── pages/
   │   ├── index.tsx         (gallery)
   │   ├── overview.tsx      (executive dashboard)
   │   └── skin/
   │       └── [slug].tsx    (skin matrix)
   ├── components/           (reusable: MarkdownRenderer, ScoreBadge, etc.)
   ├── lib/                  (data fetching, anchors)
   ├── public/               (static assets)
   ├── build.console.ts      (bun build config)
   ├── tailwind.config.js
   ├── env.d.ts              (feature flags type augmentation)
   ├── index.html            (dev server entry)
   └── package.json
   ```

5. **Implement the pages**
   - **Gallery** (`index.tsx`): reads `thumbs.json` (from `pph-tools`) and renders mock cards with status badges, clickable to view details.
   - **Overview** (`overview.tsx`): fetches `GET /overview` and renders the four blocks (cash, agents, skins, health) with nice cards and charts (simple CSS, no heavy chart libs unless needed).
   - **Skin Matrix** (`skin/[slug].tsx`): fetches `GET /skins/:slug/limits` and renders the matrix with ceiling, alias, probes, and staleness flags.

6. **Integrate with the existing pipeline**
   - The Console will be served by the same Bun server (maybe on a different port during dev, but in production we can serve static files from the `pph-api` server).
   - We'll add a `bun run console:dev` that starts a dev server with hot reload.
   - The `pph-api` server will serve the built static files in production.

7. **Add tests**
   - At least one smoke test that renders the gallery page.
   - Data‑fetching tests (mocking the API).

8. **Update the docs** – add a new section under "Console" with build instructions.
