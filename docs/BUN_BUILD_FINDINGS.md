## 1. BuildArtifact — read-only output surface (result.outputs[i])

| Property | Type (bun-types 1.4.0) | Observed on 1.4.0 (evidence) |
|---|---|---|
| kind | `'entry-point' | 'chunk' | 'asset' | 'sourcemap' | 'bytecode'` | all five observed: entry-point + asset (S01), chunk (S03), sourcemap (S04), bytecode (S06) |
| path | string | with outdir: absolute path under outdir, written (S01); without: bare `./entry.js`, NOT written (S02); outfile: ignored by the API — bare name, NOT written (S19) |
| loader | Loader | reflects the SOURCE loader: `'ts'` for a .ts entry (S01), `'file'` for a .png asset (S17) and for .map artifacts (S04); CSS asset reports `'ts'` on 1.4.0 (S01 quirk) |
| hash | string | null | non-null for entry/chunk/asset (8ccns4sx, 9qy79rr8); `'00000000'` placeholder for sourcemap artifacts (S04); identical across sourcemap modes despite different output bytes (zw9bah76 @ 215B/182B/705B, S04) |
| sourcemap | BuildArtifact | null | linked/external: nested artifact pointing at the .map (S04); inline: `null` (map base64-embedded); none: no map, no nested artifact (S04) |
| size (Blob) | number | 133 entry (S01), 58 css asset (S01), 8 png asset (S17), 352 .map (S04) |
| type (Blob) | string | `text/javascript;charset=utf-8` entry (S01), `text/css;charset=utf-8` css asset (S01), `image/png` png (S17), `application/json;charset=utf-8` .map (S04) |

Methods (S01): `.text()` `.arrayBuffer()` `.stream()` `.json()` `.slice()` present; `.formData()` `.image()` `.bytes()` ABSENT on 1.4.0; `instanceof Blob` = false (Blob-CONFORMANT, not a Blob). `.slice()` returns a PLAIN Blob (see §6).

## 2. BuildConfig — input options (passed to Bun.build())

| Option | Type (bun-types 1.4.0) | Observed effect on 1.4.0 (evidence) |
|---|---|---|
| entrypoints | string[] (required) | multi-entry + `splitting: true` → one output per entry + a shared chunk (S03: 2 entry-points + 1 chunk + 1 asset) |
| outdir | string | outputs written under outdir, absolute paths (S01); without it nothing is written (S02) |
| outfile | string | NOT honored by the API on 1.4.0: output is a bare `./pure.js`, nothing on disk at the outfile path OR cwd (S19) — type-declared but inert; use `compile: { outfile }` instead (S07d) |
| bytecode | boolean | `true` + `target: 'bun'` → an extra `bytecode`-kind output `*.jsc` alongside the entry (S06: entry-point + bytecode) |
| compile | boolean | CompileTarget | CompileBuildOptions | `true` + outdir → standalone executable written at `outdir/<entry>` (S07a, 63910514 bytes on disk, kind still `entry-point`); `compile: 'bun'` invalid — target must start `'bun-'` (S07b); `compile: true` + outfile IGNORES the outfile: the executable is named after the entry in the entry directory (S07c: `pure` at the fixture root, ~62MB) while `compile: { outfile }` honors it (S07d) |
| target | `'browser' | 'bun' | 'node'` | bun emits a `// @bun` header + 103B vs 95B for node/browser on the env fixture (S08); node/browser outputs identical for this fixture |
| format | `'esm' | 'cjs' | 'iife'` | esm: 136B `export {`; cjs: 1437B with `__defProp` helpers; iife: 1499B `(() => {` (S09) |
| minify | boolean | { whitespace?, syntax?, identifiers?, keepNames? } | 136B → 48B; object form { whitespace, identifiers, syntax } == `true` byte-for-byte (S10) |
| sourcemap | `'none' | 'linked' | 'external' | 'inline' | boolean` | none: no map (S04-none); linked: .map artifact + `sourceMappingURL` comment (S04-linked); external: .map artifact, NO comment (S04-external); inline: `sourcemap: null`, map base64-embedded (S04-inline) |
| naming | string | { entry?, chunk?, asset? } | string form applies to ENTRYPOINTS only (outn/static/pure.js, outn/static/pure2.js), chunks keep `[name]-[hash].[ext]` (outn/chunk-9qy79rr8.js); object form applies to all (outn2/e/pure.js, outn2/e/pure2.js + outn2/c/pure.js); hash-less string + multi-output css entry FAILS the build (S05c) |
| external | string[] | `external: ['zod']` keeps `import { z } from "zod"` in the output, 100B vs 490629B bundled (S15) |
| define | Record<string, string> | `define: { MODE: 'prod' }` replaces the expression with the literal `"prod"` in the output (S11, inlined=true) |
| env | `'inline' | 'disable' | 'PREFIX_*'` | NO substitution observed on 1.4.0: `process.env.GROUND_MODE` stays dynamic in all three modes with `GROUND_MODE` set at build time (S12, substituted=false) — use `define` for build-time constants |
| drop | string[] | `drop: ['console.log']` removes the call (true → false in output, 105B → 81B, S13) |
| allowUnresolved | string[] | default `['*']` lets non-literal `import()` pass through un-bundled (S14-default ok); `[]` and a glob allow-list `['./locales/*.json']` BOTH fail the build on 1.4.0 for a `"./locales/" + lang + ".json"` template (S14-empty/glob) |
| conditions | string[] | string | package.json `exports` conditions honored: local `cond-pkg` resolves `var tag = "DEFAULT";` by default and `var tag = "CUSTOM";` with `conditions: ['custom']` (S16) |
| publicPath | string | asset URLs rewritten in JS: `'/cdn/pix-6kt9k1q8.png'` with `publicPath: '/cdn/'` (S17, jsReferencesCdn=true) |
| root | string | output structure resolves against root: `rooted/app.ts` → `outr2/rooted/app.js` with root set vs `outr/app.js` without (S18) |

## 5. Blob#image() gotchas — and why BuildArtifact.image() is absent on 1.4.0

bun-types declares `BuildArtifact extends Blob`, so the Blob#image()
pipeline would be inherited — but on 1.4.0 the artifact is Blob-CONFORMANT,
NOT a Blob (`instanceof Blob` = false, S01) and `.image()` is
undefined (evidence buildArtifactImage). The gotchas below are grounded on
the REAL `Blob#image()` / `Bun.file().image()` surface (both present);
they would apply to `BuildArtifact.image()` if Bun ever adds it.

| Gotcha | Verdict | Observed on 1.4.0 |
|---|---|---|
| nothing runs until a terminal (`.bytes()`, `.write()`, `.metadata()`) | CONFIRMED | `.image()` on a garbage file returns a pipeline without throwing; only the terminal throws (`ERR_IMAGE_UNKNOWN_FORMAT`) |
| `img.width/height` are -1 until the first terminal resolves | CONFIRMED | {"w":-1,"h":-1} -> {"w":8,"h":8} after `.resize(8,8).png().bytes()` |
| HEIC/AVIF macOS/Windows-only (Linux -> `ERR_IMAGE_FORMAT_UNSUPPORTED`) | CONFIRMED (platform) | heic encode works on macOS arm64 (image:probe P12); Linux rejection not probeable here (honest pin); bad INPUT uses `ERR_IMAGE_UNKNOWN_FORMAT` / `ERR_IMAGE_DECODE_FAILED` — the unsupported code is platform-only (image:probe P13) |
| format detection by content, not extension/Content-Type | CONFIRMED | `.jpg` file with PNG bytes -> `png`; Blob typed `image/jpeg` with PNG bytes -> `png` |
| decompression-bomb guard (`maxPixels` ~268MP) | CONFIRMED | default 268402689 px (`0x3FFF * 0x3FFF (16383^2, same as Sharp)`): 16383^2 accepted, 16384^2 -> ERR_IMAGE_TOO_MANY_PIXELS (strict exceeds check); option overrides honored (`maxPixels: 100` -> 10x10 ok, 11x11 ERR_IMAGE_TOO_MANY_PIXELS) |
| no format method -> reuses source format, or dest-path extension on `write()` | CONFIRMED | `.bytes()` keeps the PNG signature + blob type `image/png`; `.write(out.jpg)` emits JPEG (true) |
| `new Response(img)` works; await a terminal in handlers | CONFIRMED (works) | content-type `image/png`, body 79B; encode-thread timing not directly measured — awaiting a terminal first keeps encode off the JS thread |
